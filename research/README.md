# DAIR research prototype v0.1

目标：动态修改下，在编辑与版本约束下减少不必要的重生成。当前仅实现离线规划，不是完整论文成果。

## 复现

Python 3.10+，无第三方依赖，在仓库根目录运行：

```bash
python -m unittest discover -s tests -v
python research/benchmark.py
python dair.py fixtures/example.json
```

`results/offline.json` 和 CSV 保存逐案例结果。每次重跑 planner_ms 会变化，其余字段确定。

## 已实现的方法

- 编辑输入为结构化的 `target / key / scope`；key 使用 `hero.costume` 这样的实体属性名。
- `reads` 明确场景消费的状态属性；支持 local / onward / global 作用域。
- 依赖边区分 order、state、reference。order 不传播失效；state 仅传播匹配属性；reference 保守传播全部素材失效。
- 对必须修改节点求失效闭包；对 uncertainty score 进行穷举子集搜索，最小化估计成本，并满足残余分数预算。
- 精确搜索仅针对这个简化、显式标注的模型，最多 20 个不确定节点。不是现实视频生成问题的全局最优算法；当前也没有并行调度延迟目标。
- 不确定分数是输入的启发式值，未经概率校准。默认预算为 0，正分数节点全部重生成。非零预算下 validation 中的复用节点必须进一步验证，规划器不会给出安全复用保证。

## 当前证据与边界

8 个手工合成案例覆盖服装、镜头、字幕、引用链、伤情状态、不同角色和全局编辑。标签仅进入评估器；规划器不读取标签。不过案例和方法共同设计，结果只用于机制检查，不能当作独立评测。

| 方法 | 完全匹配预设标签 | 累计估计成本 |
| --- | ---: | ---: |
| Full | 0/8 | 168 |
| Suffix | 0/8 | 160 |
| Untyped DAG | 0/8 | 145 |
| DAIR | 8/8 | 49 |

完全匹配指标会惩罚多余生成；Full 的 affected-scene recall 仍为 1。应同时查看 JSON/CSV 中 precision 与 recall，不能只报告完全匹配。

所有成本为任意单位，不是 API 费用或 GPU 时间。唯一实测耗时是本机规划器 CPU 时间。未测视频质量、编辑成功率、跨场景一致性、真实恢复成功率或 token usage，也未实现 LLM selection 基线。

字幕案例仅表明场景资产需要修改，尚未区分视频、字幕和音频的执行动作，不能接入视频 worker 自动执行此类计划。

现有 `worker.py revise` 仍执行保守的全部 DAG 下游失效。DAIR 与运行时尚未连接，离线计划不会自动修改数据库或提交 GPU 任务。现有恢复测试使用模拟 HTTP 服务。

关键失败模式：缺失 reads/state/reference 标注会漏掉必要修改；当前没有自动依赖提取、视觉验证或未知属性的可靠兜底。参考边失效传播刻意保守，可能多生成。依赖必须按输入场景顺序形成 DAG。

## 下一阶段验收

1. 将 Scene 扩展为视频/字幕/配音资产；增加输入指纹与素材来源版本，事务校验整个计划，再连接 worker。
2. 构建独立标注的故事与编辑事件，冻结测试集；区分规则开发集和盲测集。不要把 8 个机制案例扩写后直接宣称 benchmark 泛化。
3. 评估影响集合 precision/recall、成本差距、依赖类型与成本优化消融。为小规模实例保留穷举参考。
4. 固定模型、参考图、种子和参数，记录真实生成任务、GPU/API 成本和产物；完成编辑正确性与一致性盲评。
5. 注入提交响应丢失、重启、旧版本结果晚到等故障，分别报告状态正确性与外部重复提交；不宣称服务商 exactly-once。

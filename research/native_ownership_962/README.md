# Round 962 · 八场景实拍归属 Holdout

八个槽位均为待采集的新场景。每个槽位需要独立实物组合或独立现场，禁止拿已有论文视频、同一摆放的不同帧或生成素材充数。每个场景录制三段 4–6 秒横屏视频。用不同实物支持挑战标签，首帧旋钮中心和蓝色三角贴纸必须可供标注。每个镜头只包含一个指定旋钮和一个蓝色三角贴纸，干扰装饰可采用非蓝色标识。

| 槽位 | 拍摄重点 |
|---|---|
| 96201 | 同一机身不同表面，从固定斜角明确拍出接缝与两部件。 |
| 96202 | 同一机身不同表面，从另一视角让部分连接边界短暂不可见。 |
| 96203 | 两个相似外壳，区分同款贴纸挂在哪个外壳。 |

S1 拍同外壳的锚点，S2 将同款贴纸附在独立外壳上，S3 拍同外壳的必要候选。照实记录各场景通过或排除原因。只依据原片、实物布置和冻结挑战条件筛选，筛选者在任何方法运行前完成。遮挡或跨视角导致模型失效的片段仍应保留，只要素材本身符合上述拍摄条件。不得用方法结果补采、换种或更换标注。按 `SOURCE/96201/S1.mp4`、`S2.mp4`、`S3.mp4` 等目录命名。

## 四方法配对

需要 Python 3、FFmpeg、NumPy、SciPy、Pillow 和已加载 `qwen2.5vl:7b-ctx8k` 的 Ollama 服务。三个镜头的条件已冻结。Marker Matching 面向同贴纸设计，始终把匹配贴纸判作 same。Full-frame VLM 每镜头用五个固定分位的未标记全帧发一个请求，原始答复和模型 digest 会记录。Temporal Geometry 复用公开的跟踪与连续分离规则，并使用人工首帧点位。Oracle 接收锁定的真值。四个方法都用同一批原片，但各方法所获得的帧与人工辅助条件不同，不能称为等信息预算。

```bash
python3 holdout.py prepare --root "$SOURCE" --out review
# 复制 review/screen.template.json 到 review/screen.json。
# 按 320x178 的首帧图标注每个镜头 clicks 的两个点 [[旋钮x,旋钮y],[贴纸x,贴纸y]]。
# 补齐八个槽位的 eligible 和 reason，确认源视频条件和标注后锁定。
python3 holdout.py lock --root "$SOURCE" --out review --screen review/screen.json
python3 holdout.py score --root "$SOURCE" --out review --screen review/screen.json --lock review/input-lock.json
```

总体和挑战组均报告真值负、正候选数，门控前 FA、FR、各类弃权，门控后镜头 Coverage、Exact、错误保留、错误丢弃和 planned jobs。挑战标签可重叠，不跨挑战组求和。空分母记 N/A。planned jobs 是选中的镜头数（含 S1），服务端接受数记录为缺失，除非另做实际渲染。VLM 非法文本保留为未解析且按弃权计，服务请求失败会中止而不生成最终成绩。

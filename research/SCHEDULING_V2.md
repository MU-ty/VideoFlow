# 连续修改过程与调度路线诊断

## 五条人工设计示例

以下是替用户起草的制作需求示例，**不是实际用户行为记录**，时间仅是示意，不参与本次调参或测试。计时从当前版本开始生成时起。

1. **屋顶人物服装反复确认**：10 秒“把 S2 起人物外套改成黑色，后面出现该人物的镜头同步”；18 秒“还是改成亮宝蓝色”；28 秒“蓝色保留，只把 S2 字幕改成‘我们现在出发’”。服装影响 S2/S4/S6；字幕独立。字幕修改不应再提交视频任务。
2. **温室整体氛围撤销**：15 秒“把所有镜头的白昼改成夕阳”；30 秒“人物外套改蓝色”；45 秒“夕阳不要了，恢复原来的白昼，蓝色外套保留”。检验全局属性撤销与另一属性保留，不能把项目整个回滚。
3. **陶瓷产品颜色定稿**：8 秒“把产品主体改成蓝色，出现该产品的镜头同步”；16 秒“改深一点”；24 秒“确认深蓝，壶嘴、把手和轮廓都保持原样”。前两次是颜色修改；最后一句包含视觉保持要求，当前显式属性规划与调度模拟不能验证形状保持，须另做人审，不能当成模拟成功指标。
4. **港口短片的局部与全局交替**：12 秒“把 S2 起工人的外套改蓝色”；22 秒“所有镜头改为阴天”；36 秒“外套改回原色，阴天保留”；50 秒“只把 S2 字幕改成‘准备启航’”。检验连续局部、全局和字幕修改；字幕不进入当前仅视频服务模拟。
5. **生成未完成时反复撤销**：6 秒“白色外套改黑色”；12 秒“撤销，恢复白色”；20 秒“最终还是宝蓝色”。三个要求可能落在同一个生成周期内；旧任务仍须终结，旧白色结果不能仅因颜色相同就越过生产运行时的版本校验。

以上自然语言必须先人工明确 target/key/scope/value。本文没有实现自然语言解释器，也没有将这些示例伪装成真实编辑日志。

## 运行与比较协议

```bash
python -m unittest discover -s tests
python research/audit_schedule_runtime.py
python -u research/run_schedule_diagnosis.py --output runs/scheduling-diagnosis-v2
```

输出目录必须不存在。无需 ComfyUI 或 GPU。默认 40 条开发轨迹、40 条测试轨迹，新种子 61000/81000 系列，与 V1 分离，但仍来自同一个合成生成器。五种修改时间模式和四种部署条件均衡覆盖。

每类策略 32 个候选；比较全局调优固定/自适应、分部署条件调优固定/自适应，以及 FIFO、最新优先、短任务优先。分组仅使用运行前已知的就绪规则与缓存能力，不能使用未来才知道的“突发/稀疏”等标签。分组调优可能因样本更少而不如全局调优，两者全部报告，不能挑弱基线。

在评估前写入 protocol.json 和 selection.json。冻结目标为最后修改延迟 + 0.25×未使用服务量 + 0.1×不可用素材暴露时间。时间是声明成本范围下的模拟时间，不是测得 GPU 秒。

额外报告 64 个候选在每条完整测试轨迹上的事后最佳值。这只能诊断有限候选集的剩余空间，使用了未来信息，不是可部署策略、真实最优值或通用下界。

## 模拟与运行时的差异

| 项目 | V1 | 本轮处理与剩余限制 |
|---|---|---|
| 撤销后旧结果复用 | 按语义键跨版本复用 | revision 模式拒绝跨版本复用；实际 SQLite 探针验证旧结果 stale |
| 就绪规则 | ordered 要求所有前序节点当前有效 | runtime_edges 只检查直接入边；实际探针验证 A/C 失效而 B 保留时 C 可以就绪 |
| 状态/参考依赖 | 简化成显式属性值；拒绝 reference | 仍没有参考图像生成，不能用于该类结论 |
| 观测延迟 | 完成即观测 | 仍未模拟实际 5 秒轮询 |
| 服务时间 | 每输入确定性抖动 | 未标定冷启动、模型装卸、CPU 编解码、任务相关时长 |
| 远端工作 | 单 FIFO、非抢占、上限 2 | 所有策略保留旧任务到终结；没有真实队列删除、失败或恢复 |
| 视觉质量 | 符号键正确 | 不证明外套颜色、身份、形状或画面保持 |

runtime_edges/revision 只是更接近生产语义的切片，不能称为生产系统的完整复现。V1 文件与负结果完整保留。

## 本轮结果与决策

40 条测试轨迹：全局固定目标值 566.312，全局自适应 590.992；分条件固定 573.597，分条件自适应 597.615。分条件固定并没有超过全局固定，所以两种固定基线都必须保留。

更接近生产的 runtime_edges/revision 切片：分条件固定 508.412，自适应 554.864，自适应目标值恶化约 9.14%。该切片有限候选事后最佳为 490.100，较分条件固定约低 3.60%；这不是所有调度方法可能收益的上限。

**结论：暂停当前自适应等待/排序候选及其真实 GPU 实验。** 这不等于证明连续修改调度没有研究价值，也不支持继续以当前候选作为论文主创新。只有出现独立于这些合成轨迹的新动机、真实编辑时间日志或实测服务模型，再重新立项；不要在已看过的测试集上反复调参以争取正结果。当前 VideoFlow 的版本安全执行与案例证据可以保留，论文须明确与属性级基线持平以及调度负结果。

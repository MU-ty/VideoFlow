# Budgeted dependency verification

## Experiment 930

The locked protocol defines 12 new source seeds across four scenarios. Each target position (S2, S3, S4) appears four times. For each position, the target is the graph parent twice and the distractor is the parent twice. Each seed has two probe candidates, one edit anchor, two reference descendants and one unrelated shot. The primary budget is three total VLM calls, with two, four and five as secondary budgets.

All policies start with the same single call per candidate. Round-robin alternates from a preassigned start, fixed recheck exhausts that starting candidate's available rechecks first, uncertainty uses the same frozen scoring rule as 927, and graph weighting multiplies it by the marginal closure size. Oracle selects ground-truth candidate labels and measures a closure reference without VLM verification. The bank uses identical inputs and model settings across policies.

Locally validated all 12 initial manifests in the real VideoFlow runtime. Source rendering and VLM collection require running H3/ComfyUI and Ollama endpoints, FFmpeg/ffprobe on PATH, and the configured model tag.

From the extracted directory:

```bash
protocol=VideoFlow_Active_Budget/holdout_930_protocol.json
src=runs/egdr-active-source-930
bank=runs/egdr-active-holdout-930

python3 -u VideoFlow_Active_Budget/generate_sources.py \
  --protocol "$protocol" --output "$src"
```

Before collection, fill `$src/source-screen.csv` using the frozen sheets. For S1 and the case's `expected` candidate use the target marker. For the other candidate use the distractor marker. Count from 0 to 4 panels in which both marker and part are visibly linked to the correct host. Each of the three screened shots needs at least one qualifying panel. Keep every source record, including failures and exclusions.

```bash
python3 -u VideoFlow_Active_Budget/active_budget.py \
  --source-run "$src" --screen "$src/source-screen.csv" \
  --protocol "$protocol" --output "$bank"
python3 VideoFlow_Active_Budget/budget_metrics.py \
  --cohort 930 --protocol "$protocol" \
  --report "$bank/report.json" --output "$bank/metrics.csv"
```

Metrics report micro precision, recall and F1, exact candidate sets, missed/excess candidates and planned graph-closure counts. This stage measures replayed allocation. The VLM bank includes eight actual calls per completed source; the per-policy budget counts revealed replies.

## Primary-budget paired execution

On the H3 host used to create Rev.1, with an idle dedicated ComfyUI queue and accessible original provider outputs:

```bash
python3 -u VideoFlow_Active_Budget/execute_pair.py \
  --protocol "$protocol" --source-run "$src" --screen "$src/source-screen.csv" \
  --bank "$bank" --output runs/egdr-active-pair-930
```

Add `--prepare-only` and use a separate output directory to check input and bank hashes and replay agreement without contacting ComfyUI. The runner executes all eligible pairs in the primary three-call setting. Both arms fork the same Rev.1 database, apply their frozen bank decisions through the same publication gate, and execute on the same H3 backend. Pair order alternates across sorted eligible blocks. Collect `report.json` and the per-arm `summary.json` files. Retain failed runs and their logs; the runner leaves them on disk and stops on the first failure. Start any retry with a new output directory.

The edit timing starts after bank collection; it measures publication after a single edit with the bank already available. Report acknowledged submissions and completed jobs separately, and check sampler cache records before interpreting latency differences. Alternating order reduces a systematic order preference, but provider caching can still affect individual pairs. Missing provider history makes cache status unknown. The runner compares the first published closure with the required set and checks reference lineage and retained artifact hashes. Visual edit quality requires separate inspection of the output clips. GPU seconds are left unset.

For the local simulated-provider regression check:

```bash
python3 VideoFlow_Active_Budget/test_execute_pair.py
```

## Archived results

The bundled CSVs use five eligible original seeds in each round. Round 926 uses the original bank, preserving its candidate order and validating prompt, model identity, archived frame hashes, votes and original scores. Round 927 uses the archived aggregate report. Its budget-2 candidate and closure results follow from the shared rule: a single view cannot reject a candidate. The fixed-first-focus policy needs raw per-call votes and is therefore reported only for 926. Fixed S2/S3 start controls in both rounds are round-robin policies with designated starting candidates.

At three calls, both rounds reached 4/5 exact for uncertainty and 2/5 for round-robin. They tied at 4/5 upon four calls. Graph weighting tied uncertainty at three and four calls, then dropped to 3/5 on 926 with five calls while uncertainty remained at 4/5. The archives use different seeds but share story templates, so these comparisons do not establish cross-story generalization.
